# 코드 주석

주석은 다음에 이 코드를 읽고 고칠 사람을 위한 것 — 장황하면 읽기 힘들고 코드가 안 보임

## 무엇을 쓰나

**코드만 봐서는 알 수 없는 것만** 쓴다

- 왜 이렇게 했는지 — 다른 방법을 쓰면 무엇이 깨지는지
- 지켜야 하는 조건 — 순서를 맞춰야 하는 다른 코드, 같이 바꿔야 하는 곳
- 도메인 규칙 — 코드 이름만으로 드러나지 않는 정책 (egress 금지 패턴, 로컬 타임존 등)

## 쓰지 않는 것

- 코드를 한국어로 다시 읽어 주는 설명 (`// 설정 읽기`, `// 빈 배열 리턴`)
- 개발 과정 이야기 — 세션 대화에서 나온 검토 경위, 이전 구현과의 비교, 리뷰 반영 내역, "(실측)" 같은 출처 메모. 이건 커밋 메시지 · PR · `docs/decisions`에
- 문서에 이미 있는 내용의 반복 — 길어지면 해당 `.claude/rules/` 문서로 옮기고 주석은 한 줄

## 형식

- 한두 줄. 길어지면 정말 필요한 내용인지 먼저 의심
- 명사형 종결 (`~함`, `~됨`, `~음`), 끝에 마침표 X — 커밋 메시지와 같은 문체
- 내부 식별자 · 문서 번호 인용 금지 — ADR 번호, plan 섹션 번호, 이슈/PR 번호. `docs/`는 로컬 전용(gitignore)이라 공개 레포에서 따라갈 수 없음. "우리" 같은 화자 표현도 X
- 인터페이스 · 타입 · 반환 타입의 필드 설명은 그 줄 옆 `//`로. 필드마다 위에 `/** */`를 쌓으면 필드가 설명에 묻혀 구조가 안 보임
- `eslint-disable` 처럼 도구가 요구하는 주석은 예외

```ts
// ✅
dailyCount: number; // 주·월간은 활동일 수, 연간은 포함된 월 수

// ❌
/** 주·월간은 활동일 수, 연간은 포함된 월 수 */
dailyCount: number;
```

```ts
// ✅
// 미로그인·토큰 만료는 subtype 'success' + is_error 로 옴 — 결과 텍스트를 잡아두지 않으면 SDK 가 빈 값을 던질 때 원인이 사라짐

// ❌ — 코드를 읊고, 이 처리를 넣게 된 경위까지 설명
/**
 * is_error 결과의 result 텍스트를 errorResult 변수에 저장한다
 *
 * 이렇게 하는 이유:
 * - dmg 설치본에서 연결됨인데 발행이 실패하던 문제를 조사해 보니 ...
 * - 이전 구현은 subtype 만 봤기 때문에 ... (ADR 0021 참고)
 */
```
