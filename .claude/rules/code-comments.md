# 코드 주석

코드만 봐서는 알 수 없는 것만 쓴다.

- 쓰는 것: 왜 이렇게 했는지(다른 방법이면 무엇이 깨지는지), 지켜야 하는 조건(순서를 맞출 코드, 같이 바꿀 곳), 이름에 드러나지 않는 도메인 규칙(egress 금지 패턴, 로컬 타임존 등)
- 쓰지 않는 것: 코드를 다시 읽어 주는 설명, 개발 경위(검토 과정·이전 구현 비교·리뷰 반영·"(실측)" 같은 출처 메모 — 커밋·PR·`docs/decisions` 로), rules 문서 내용 반복
- 한두 줄. 명사형 종결(`~함`, `~됨`, `~음`), 끝에 마침표 X
- ADR·plan·이슈/PR 번호 인용 금지 — `docs/` 는 로컬 전용이라 공개 레포에서 따라갈 수 없음. "우리" 같은 화자 표현 X
- 인터페이스·타입 필드 설명은 그 줄 옆 `//` 로 (`dailyCount: number; // ...`). 필드마다 `/** */` 를 쌓지 않음
- `eslint-disable` 처럼 도구가 요구하는 주석은 예외
